## ١. الهدف في سطرين
قائمة جانبية في كروم تجمع أدواتنا **كودجات** تُرتَّب وتُنقل بسهولة، تبدأ بساعة البكور وتتسع لأدوات جديدة مع الوقت، وتصير لاحقاً منصة بحسابات مستخدمين.

## ٢. القرارات المتخذة
- 🟢 **البداية بالساعة** — أول ودجة تُبنى.
- 🟢 **قائمة جانبية** بودجات سهلة **إعادة الترتيب وتغيير المواضع**.
- 🟢 **نطوّرها مع الوقت**، وكل تحديث يظهر أولاً بأول؛ و**حسابات مستخدمين مستقبلاً**.
- 🟢 **القائمة صفحة ويب مستقلة تُستدعى** داخل الإضافة (لا كود مدمج فيها).
- 🟢 **المستودع: BUKUR.**
- (ملاحظة) يوجد مشروع Firebase باسم **BUKUR** (`bukur8`، خطة Spark المجانية، بلا تطبيقات بعد) — من لقطة شاشة المالك.

## ٣. البنية: «غلاف رفيع + تطبيق ويب» 💡

```
┌──────────── كروم ────────────┐
│ صفحة أي موقع │ القائمة الجانبية │
│              │ ┌──────────────┐ │
│              │ │ غلاف الإضافة  │ │  ← extension/ : صغير، نادراً ما يتغيّر
│              │ │ ┌──────────┐ │ │
│              │ │ │ تطبيق    │ │ │  ← app/ : مستضاف (Firebase Hosting)
│              │ │ │ الودجات  │ │ │     يتحدّث فوراً عند كل رفع
│              │ │ └──────────┘ │ │
│              │ └──────────────┘ │
└──────────────────────────────┘
نفس app/ يعمل أيضاً: في تبويب كامل («التوسيع») · وعلى الجوال كتطبيق ويب (PWA)
```

- **`app/`** — كل شيء: الحاضنة، الودجات، الإعدادات، والحسابات لاحقاً.
- **`extension/`** — إضافة Manifest V3 تفتح القائمة الجانبية وتعرض `app/` داخل إطار (iframe)، وزر «افتح في تبويب كامل».
- **لماذا:** التحديث المستمر بلا إعادة تثبيت، والحسابات مكانها الويب، وصفحة واحدة لكل الأجهزة. وكروم يمنع تشغيل كود مجلوب من الإنترنت **داخل** الإضافة، لكنه يسمح بعرض موقع داخل إطار (ثقة ~٨٠٪).

## ٤. عقد الودجة 💡
كل ودجة مجلد مستقل في `app/widgets/<id>/` بالشكل نفسه — إضافة أداة جديدة = إضافة مجلد، دون تعديل الحاضنة.

```js
// app/widgets/bukur-clock/index.js
export default {
  id: 'bukur-clock',            // ثابت للأبد — مفتاح التخزين
  name: 'ساعة البكور',
  icon: './icon.svg',
  sizes: ['s', 'm', 'l'],      // الأحجام المسموحة
  defaultSize: 'm',
  mount(el, ctx) {             // يرسم الودجة داخل el
    // ctx.store   → مخزن خاص بهذه الودجة فقط: get/set/subscribe
    // ctx.size    → الحجم الحالي، ويتغيّر بـ ctx.onResize
    // ctx.bridge  → قدرات المتصفح عبر الغلاف (لاحقاً؛ قد يكون غير متاح)
    return () => { /* تنظيف عند الإزالة */ };
  },
  settings: { /* اختياري: إعدادات تُعرض في قائمة الودجة */ },
};
```

**قواعد العقد:**
- الودجة **لا تلمس** DOM خارج `el`، ولا تخزين غيرها، ولا متغيرات عامة.
- الودجة **تعمل في أي عرض**: عمود القائمة الضيق، أو شبكة التبويب الكامل.
- منطق الحساب (الوقت، اليقظة…) في **دوال نقية منفصلة** تُختبر دون متصفح.

## ٥. الحاضنة (صفحة الودجات) 💡
| | القائمة الجانبية (ضيّقة) | التبويب الكامل («التوسيع») |
|---|---|---|
| الترتيب | عمود واحد، سحب لأعلى/أسفل | شبكة، سحب إلى أي خانة |
| لكل ودجة | طي/فتح · تغيير الحجم · إعدادات · إخفاء | نفسها |
| «أدواتي» | قائمة لإظهار وإخفاء الودجات | نفسها |

- **الحفظ:** الترتيب وحالة كل ودجة محلياً الآن (`localStorage`)، وعبر الحساب لاحقاً — الواجهة نفسها `ctx.store` فلا تتغيّر الودجات.
- **تصدير/استيراد** الإعدادات كملف JSON.
- **العربية أولاً واتجاه RTL**، وهوية Mind8x: أخضر داكن، برتقالي للإبراز، بيج للأرضية.
- **بلا إطار ولا خطوة بناء** (JavaScript عادي بوحدات ES) — نفس فلسفة إرث: سريع، رخيص، لا يتكسّر بالترقيات.
- ⚠️ عرض القائمة الجانبية يغيّره المستخدم بسحب حافتها، والإضافة لا تضبطه برمجياً (ثقة ~٨٠٪)؛ لذا «التوسيع» = تبويب كامل.

## ٦. الودجة الأولى: ساعة البكور 💡
**المصدر:** `index.html` الحالي (ساعة «AL DHAFAR 3»).

**ما يُنقل كما هو (الشكل والحسابات):**
- قرص ٢٤ ساعة بعقارب الساعات والدقائق والثواني والتاريخ.
- الإطار الدوّار يُسحب لتحديد وقت الاستيقاظ · زر «استيقظت الآن» · «تصفير» · وقت استيقاظ يومي بالساعة والدقيقة.
- ساعات اليقظة والحالة (نشيط · فعّال · متعب · نَم!) وشريط تقدّم اليقظة.
- أوضاع القرص: أبيض / ليل-نهار (١٨–٠٦ أو ١٩–٠٥)، وتدرّج الليل ثابت/متتبّع، ووضع الإطار يقظة/ليل-نهار.

**ما يتغيّر:**
- إعادة كتابة بلا React وBabel وTailwind من الإنترنت → JavaScript عادي وSVG. (السبب: الإضافات تمنع الكود المجلوب، وBabel في المتصفح بطيء ويتطلب `eval`.)
- الحسابات تخرج إلى `app/widgets/bukur-clock/time.js` (دوال نقية) ولها اختبارات.
- الإعدادات عبر `ctx.store` بدل مفتاح `aldhafar3` مباشرة — مع **ترحيل تلقائي** من المفتاح القديم حتى لا يضيع إعداد أحد.
- الأحجام: صغير (القرص فقط) · متوسط (القرص + الأزرار) · كبير (مع الإعدادات).
- **`index.html` الحالي يبقى يعمل** حتى تُثبت الودجة الجديدة أنها مطابقة.

**ملاحظة من قراءة الكود:** ساعات اليقظة تُحسب بباقي القسمة على ٢٤، فبعد ٢٤ ساعة يقظة تعود للصفر. نُبقيها كما هي الآن، ونسأل المالك ❓.

## ٧. الغلاف (الإضافة) 💡
- Manifest V3، صلاحية `sidePanel` فقط في البداية — أقل صلاحيات ممكنة.
- صفحة القائمة = إطار يعرض رابط `app/` المستضاف + زر «افتح في تبويب».
- تُثبَّت من «وضع المطوّر» أولاً، والمتجر لاحقاً إن أردنا.
- **الجسر (لاحقاً):** رسائل `postMessage` بين `app/` والغلاف لقدرات المتصفح (تجميع التبويبات، الكتم، التنبيهات) — مع قائمة بيضاء للنطاق المصدر. لا تحتاجه الساعة.

## ٨. الاستضافة والحسابات 💡
- **الاستضافة:** Firebase Hosting في مشروع `bukur8` (متاح في الخطة المجانية) — أو أي استضافة ثابتة. ❓
- **الحسابات لاحقاً:** Firebase Authentication هو المرشّح الطبيعي في نفس المشروع.
- ⚠️ **خطر يجب اختباره مبكراً:** داخل إطار في إضافة، يعامل كروم الموقع كطرف ثالث فقد يحجب أو يعزل التخزين والكوكيز، فيتعطّل تسجيل الدخول (ثقة متوسطة). **تجربة صغيرة** (المرحلة ٤) قبل بناء أي شيء على الحسابات. البدائل المعروفة: الدخول في تبويب كامل وتمرير الرمز عبر الغلاف.
- 💡 **الدفع (سؤال المالك ٨ نوفمبر: «هل ممكن أن تكون بوابة الدفع واحدة؟»):** نعم — **بوابة واحدة (Tap) وحساب واحد لكل منتجات Mind8x**، متّسقاً مع قرار المنصة «حساب واحد يشتري منه المستخدم كل شيء». الشكل المقترح:
  - خدمة حسابات ودفع مركزية تحت `mind8x.com` (مثلاً `account.mind8x.com`)، والمنتجات (`bukur.mind8x.com` وغيرها) تسأل: «ما الذي يملكه هذا المستخدم؟».
  - تأكيد الدفع عبر **إشعار Tap إلى الخادم (webhook) يُتحقَّق من توقيعه** — لا يُصدَّق المتصفح أبداً.
  - ⚠️ يحتاج خادماً: Cloud Functions في Firebase تتطلب خطة Blaze (الدفع حسب الاستهلاك)؛ البديل Cloudflare Workers (مجاني في حدود) — يُقرَّر لاحقاً.
  - 🟢 **قرار المالك (٨ نوفمبر ٢٠٢٦): كل المنتجات تحت نفس المنصة** — البكور وإرث (Erthi) وما يأتي بعدهما: حساب واحد وبوابة دفع واحدة.
- 🔒 **المستودع عام:** لا أسرار فيه أبداً. إعدادات Firebase للويب ليست أسراراً، لكن أي مفتاح خادم أو كود خادم للحسابات يكون في مستودع خاص.

- 🟢 **شارة المؤقت فوق أيقونة الإضافة** (فكرة المالك وموافقته): رقم الدقائق المتبقية بلون المرحلة (فيروزي ← أصفر ← برتقالي ← أحمر، والراحة أزرق، والموقوف رمادي، والتصاعدي فيروزي بالدقائق المنقضية، و✓ أخضر عند الانتهاء). **يبقى وإن أُغلقت القائمة**: الإضافة تحفظ لحظة الانتهاء وتحدّث الشارة بمنبّهات `chrome.alarms` كل نصف دقيقة.
  - المسار: المؤقت ← `app/bridge.js` ← (في القائمة) postMessage للأب `panel.js` الذي يتحقق من مصدر الإطار ← خلفية الإضافة؛ (في تبويب كامل) `chrome.runtime.sendMessage` بمعرّف الإضافة الذي تعطيه القائمة للصفحة، و`externally_connectable` يقصره على نطاق البكور. الخلفية تفحص شكل كل رسالة قبل قبولها.
  - صلاحيات جديدة: `alarms` (موافقة المالك) و`storage` (لـ `chrome.storage.session`: الحالة في الذاكرة ما دام المتصفح مفتوحاً، بلا كتابة على القرص؛ بلا تحذير عند التثبيت). الإضافة ٠٫٢٫٠، وتحتاج Chrome ١٢٠+.
  - ⏳ حدود: السلسلة التلقائية لا تُكمل في الشارة والقائمة مغلقة (تظهر ✓ عند انتهاء المرحلة، والصفحة تكمل حين تُفتح)؛ وإشعار النظام عند الانتهاء مؤجّل.
- 🟢 **أداء «خارطة النجوم»** (موافقة المالك): كانت تعيد رسم الخارطة كلها ٦٠ مرة/ث (`requestAnimationFrame`) ← مرة كل ثانية، ولا رسم والصفحة مخفية. القياس: المعالج ١٤٪ ← ٠٫٣٪، وعناصر الصفحة ٨٥٬٠٥١ ← ١٠٬٠٢٣.
- 🟢 **ودجة «المخطط» (جانت)** (طلب المالك؛ من مستند البكور §٤ «جانت للأسابيع والأشهر، البكور لليوم» ومن أدوات K): **المعيار الرئيسي والفرق عن تقويم Google وOutlook**: مهما كان التقسيم تبقى المهام ونسب إنجازها ظاهرة داخله.
  - **زر واحد متعدد الضغطات** يدور: سنة (شبكة ١٢ شهراً × ٣١ يوماً كتقويم AnuCal الذي أشار إليه المالك) ← موسم ← شهر ← أسبوع ← يوم. السابق/التالي يتحرك نطاقاً كاملاً، وزر «اليوم».
  - **أنظمة المواسم كلها** بزر ثانٍ (قرار المالك: «كلهم، والشخص يفعّل ما يحتاج»): مواسم النجوم والطوالع (من بيانات «خارطة النجوم»: السنة تبدأ ٦ سبتمبر بالجبهة) · الفصول الفلكية (تواريخ تقريبية ±يوم) · أرباع السنة. لون موسم كل يوم يظهر خلف شبكة السنة وشريطاً فوق جانت.
  - **المرحلة الأولى (قرار المالك)**: مهام بمدة ولون ونسبة إنجاز؛ الممتلئ من الشريط يتبع خط زمن المهمة (مهمة تمتد شهرين منجزة ٥٠٪ يمتلئ شهرها الأول فقط). شارة إنجاز النطاق موزونة بالأيام. ⏳ لاحقاً: الخطط والأهداف من العشرية إلى اليومية فوق المهام، وربط Google/Outlook.
  - 🟢 **الفرز بالتصنيف وشكل AnuCal** (طلب المالك بلقطة من app.anucal.com): ست تصنيفات بألوانها (عمل · تعلّم · شخصي · صحة · أسرة · مزرعة) أزراراً في الأعلى، كل زر يُظهر أو يخفي مهام تصنيفه وعليه عددها في النطاق المعروض، وزر 👁 للكل. الفرز يسري على كل العروض وعلى نسبة الإنجاز. السنة صارت كـ AnuCal: رقم اليوم وحرفه في كل خانة، وظل للجمعة والسبت، واليوم في دائرة حمراء، وأيام ما بعد نهاية الشهر مخطّطة، وأسماء المهام على أشرطتها؛ ولون الموسم صار خطاً رفيعاً أعلى كل خانة. المهام القديمة بلا تصنيف تبقى بلونها وتظهر دائماً.
  - 🟢 **دمج المهام والتقويم في أداة واحدة** (رؤية المالك: Google يفصل Tasks عن Calendar، ونحن ندمجهما). **القائمة الجانبية** (قرار المالك) تعرض ما يلزم اليوم فقط، بزر متعدد الضغطات: اليوم ← الأسبوع يوماً يوماً (لكل يوم سطر بمهامه ونسبها) ← الشهر الحالي والقادم ← الفترة الحالية والتالية بحسب النظام (موسم / طالع / **منزلة** — أُضيف نظام المنازل الـ٢٨). **السنة والشهر الكامل والموسم الكامل في التبويب الكامل فقط**، ويتبدّل العرض تلقائياً عند الانتقال بينهما.
  - 🟢 **عطلة نهاية الأسبوع الرسمية** من ⚙: السعودية والخليج (الجمعة والسبت، افتراضي) · أمريكا وأوروبا (السبت والأحد) · الجمعة فقط · بلا عطلة، أو أيام مخصّصة بأزرار الأيام السبعة. تظلّل السنة وجانت والأسبوع.
  - 🟢 **«لاحقاً»: المهام بلا موعد في النظام نفسه** (قرار المالك: «إذا مهام ما لها تاريخ يصنّفها في فئة خاصة فقط»). المهمة بلا تاريخين تُحفظ كغيرها (بتصنيفها ونسبتها) وتظهر في صندوق «لاحقاً» تحت كل العروض، لا في التقويم. **السحب**: من «لاحقاً» إلى يوم يجدولها (خانة السنة، أو يوم الأسبوع، أو رأس جانت، أو موضع في صف جانت)؛ وسحب مهمة مجدولة إلى يوم آخر ينقلها بمدتها؛ وسحبها إلى «لاحقاً» يلغي موعدها (وكذلك زر 📥 في محرّر المهمة). زر 📥 بجانب ＋ يضيف مهمة بلا موعد.
  - إصلاح في الحاضنة: سحب نقل البطاقات كان يلغي أي سحب داخل الودجات؛ الآن يخص البطاقة نفسها فقط.
  - 🟢 **أربعة ترتيبات للسنة** (طلب المالك: «الأشهر لا تبدأ بيوم الأسبوع نفسه»)، بزر متعدد الضغطات يظهر في عرض السنة: **بالتاريخ ١–٣١** (تختلف نهايات الأشهر) ← **محاذاة باليوم** (٣٧ عموداً؛ أول كل شهر في عمود يومه، فتتطابق أيام الأسبوع رأسياً) ← **مقسّم أشهراً** (١٢ تقويماً صغيراً، نقاط بألوان تصنيفات مهام كل يوم، والضغط يفتح ذلك اليوم) ← **مقسّم أسابيع** (صف لكل أسبوع × ٧ أيام، ٥٣ أسبوعاً لـ٢٠٢٦، وخط عند أول كل شهر). **بداية الأسبوع** في ⚙ (الأحد افتراضاً). **رؤوس الأعمدة** (طلب المالك): في «بالتاريخ» أرقام الأيام ١–٣١ أعلى الأعمدة (رقم اليوم بالأحمر)، وفي «محاذاة باليوم» حروف الأيام؛ والخانات صارت بلا نص (التاريخ الكامل في التلميح)، واليوم خانة حمراء، والرأس ثابت عند التمرير.
  - 🟢 **المحرّك العام: فترة × صفوف × أعمدة ← خلايا** (نموذج المالك، وأكّد القاعدة: **الصف يحتوي العمود، والخلية بوحدة العمود**). الوحدات: يوم · أسبوع · منزلة · شهر · طالع · موسم (بنظام المواسم المختار)، وعمودان موضعيان: رقم اليوم داخل الصف، ومحاذاة يوم الأسبوع. الفترات: سنة ميلادية · سنة نجمية (٦ سبتمبر). `buildGrid` يبني أي تركيبة صالحة ويرفض غيرها، و`gridBars` يمدّ أشرطة المهام على الخلايا التي تمسّها. المحرّك يعيد إنتاج العروض الحالية في اختباراته (أشهر × رقم اليوم = ١٢×٣١، أشهر × يوم الأسبوع = ٣٧ عموداً، أسابيع × يوم الأسبوع = ٥٣ صفاً).
    - أول تركيبتين (قالبان في زر ترتيب السنة): **مواسم × أشهر** (سنة ميلادية؛ صفوف المواسم بالنظام المختار، والأشهر مقصوصة عند حدود الموسم) و**طوالع × منازل** (سنة نجمية؛ ١٣ صفاً و٢٨ منزلة). الخلية تحمل اسمها وبداية مدتها، والخلية التي فيها اليوم بإطار أحمر.
    - 🟢 **أزرار البناء الثلاثة** (موافقة المالك): في عرض «تقويم» (كان «سنة») أزرار **الفترة · الصفوف · الأعمدة**، كل زر يدور على الصالح فقط (الصفوف لا تتجاوز الفترة، والأعمدة يحتويها الصف)، وتغيير الفترة يصحّح الصفوف والأعمدة تلقائياً. وزر **القوالب** يضبط الثلاثة بضغطة، ويُظهر «مخصص» حين لا تطابق قالباً.
    - 🟢 **العقد صفاً واحداً** (طلب المالك): وحدة «عشر سنوات» للصفوف، فقالب **«عشر سنوات (١٠ خلايا)»** = صف واحد، كل خلية سنة، والمهام الممتدة سنوات أشرطة عليها؛ وبقي **«الخطة العشرية (١٠ × ١٢)»**.
    - 🟢 **دمج التقويم في الشهر والموسم والأسبوع** (طلب المالك): العرض الافتراضي صار تقويماً (أسابيع × أيام بالمحرّك نفسه، أيام الأسبوع في الرأس، والمهام أشرطة على أيامها)، وزر يبدّل إلى جانت (صف لكل مهمة) والعكس.
    - 🟢 **فترات جديدة**: عشر سنوات · سنة ميلادية · سنة نجمية · موسم · طالع · شهر · منزلة · أسبوع؛ والتنقل يتحرك فترة كاملة (العشر بالسنوات لا بالأيام). **الخطة العشرية** = عشر سنوات × سنوات × أشهر.
    - 🟢 **العروض القديمة صارت قوالب في المحرّك نفسه** (استيعاب ما بنيناه): بالتاريخ ١–٣١ (أرقام في الرأس وخانات بلا نص) · محاذاة باليوم (حروف في الرأس) · مقسّمة أسابيع (أرقام داخل الخانات) · مواسم × أشهر · طوالع × منازل · شهر × أسابيع · الخطة العشرية؛ ويبقى «١٢ شهراً صغيراً» عرضاً خاصاً. ظل العطلة وخط الموسم والأحمر لليوم والسحب إلى الخلايا كلها في العارض العام. الإعداد القديم (`yearLayout`) يُرحَّل إلى قالبه. الأعمدة المشتركة بين كل الصفوف (أشهر الخطة العشرية) تنتقل أسماؤها إلى الرأس.
  - المنطق في `planner/plan.js` باختباراته (`test/plan.test.mjs`).
- 📌 **قرار المالك (ترتيب العمل)**: كل ما يتصل بالحسابات مؤجّل — تسجيل الدخول، والدفع، وربط تقويم Google وOutlook، والمزامنة بين الأجهزة. **الهيكلة أولاً**: نموذج البيانات والتقويم (المحرّك العام) والأدوات، والتخزين محلي في المتصفح حتى ذلك الحين.
## ١٤. التموضع والإطلاق (اقتراح ينتظر قرار المالك، ٨ نوفمبر ٢٠٢٦)
> المالك سأل: هل نسوّق البكور أداةً واحدة لكل أفكارنا الخفيفة، يختار المستخدم منها ما يناسبه؟ هذا رأي Claude، سجّله المالك ليُقرَّر لاحقاً. **لم يُعتمد بعد.**
- 💡 **الفكرة مناسبة كمرحلة أولى** (ثقة متوسطة–عالية)، والبنية جاهزة لها: كل أداة ودجة مستقلة، حساب واحد، ودجات مجانية وأخرى مدفوعة.
- 💡 **بشرط وعد واحد واضح** بدل «حاوية لكل شيء»: مثلاً «البكور: يومك من الفجر — وقتك وتركيزك في متصفحك». كل ودجة تُضاف تخدم هذا الوعد.
  - تخدمه الآن: الساعة، المؤقت، خارطة النجوم، أقوال الأعلام (إلهام). لاحقاً: الأوقات اليومية، مهام اليوم.
  - ما لا يخدمه يُؤجَّل وإن سهل بناؤه.
- 💡 **جمهور أول صغير:** الباحثون وطلاب الدراسات العليا (من مستند Mind8x).
- 💡 **قياس قبل التوسّع:** أي ودجة تُستعمل أسبوعياً وأيها تُخفى — عدّاد محلي أو استبيان، **بلا تتبّع خارجي دون موافقة**.
- ⚠️ **المخاطر:** التشتّت (مستند ٠٢: «بطاقة لا تُفتح أسبوعين تُخفى»)، منافسة صفحات البداية والإضافات الجامعة (التميّز في الهوية والمحتوى العربي الموثّق لا في الودجات)، القائمة الجانبية على كروم الحاسوب فقط (الجوال يحتاج PWA).
- 💡 **ترتيب ما قبل الإطلاق العام:** ١) نشر الإضافة في متجر كروم (سياسة خصوصية ومراجعة) ← ٢) الحسابات (واختبار الدخول داخل الإطار) ← ٣) الدفع (Tap) ← ٤) الودجات المدفوعة. ويسبقها إصلاح أداء الساعة الاحترافية.
- ❓ **ما يغيّر الرأي:** إن كان الهدف تجربة الأفكار داخلياً فقط فالحاضنة المفتوحة تكفي؛ وإن أظهر القياس اختيارات متباعدة جداً فـ«اختر أدواتك بحرية» أصح؛ ووجود منافس عربي بنفس المزيج يغيّر التموضع.
- 📌 **قرار المالك الحالي:** يواصل أولاً تطوير النسخة الحالية حتى تكتمل كما يريد، قبل أي تسويق.

## ١٥. فكرة جانبية: «ورقة اليوم» كالتقويم الورقي (فكرة المالك، ٨ نوفمبر ٢٠٢٦ — لم تُبدأ)
> المالك: «التقاويم الورقية التي تأتي باليوم وحكمة اليوم والطالع… نعملها بعد ذلك، خلها فكرة جانبية الآن». الهدف: توحيد أدواتنا في أداة يمكن أن تتحول إلى **منشورات لحسابات التواصل** أو **تقاويم مطبوعة تُباع** مستقبلاً.
- 💡 **ورقة يومية واحدة تجمع ما بنيناه:** التاريخ الميلادي والهجري · **الطالع = المنزلة/النجم الطالع** من «خارطة النجوم» (بمعناه في التقاويم العربية: النوء والمنزلة، لا التنجيم والأبراج) · **حكمة اليوم** من «أقوال الأعلام» (الموثّقة بمصدرها فقط) · أوقات اليوم من ساعة البكور.
- 💡 **مصدر واحد، ثلاثة مخرجات:** (١) ودجة «ورقة اليوم» في البكور · (٢) صورة يومية جاهزة للنشر (مقاس منشور/قصة) · (٣) ملف طباعة لتقويم سنوي (٣٦٥ ورقة) يُولَّد من البيانات نفسها.
- ⚠️ **قبل البدء:** (أ) لا حكمة بلا مصدر — القاعدة نفسها في «أقوال الأعلام»، والمخزون الحالي ١٢ قولاً فقط (يكفي أسبوعين، لا سنة) · (ب) «الطالع» بمعنى المنازل لا الأبراج، ويُوثَّق مصدر التواريخ (تقويم المنازل في «خارطة النجوم») · (ج) حقوق الصور والنصوص للطباعة التجارية (صور ويكيميديا لها رخص مختلفة) · (د) الهجري: أي تقويم يُعتمد (أم القرى؟).
- ⏳ يُبدأ بعد اكتمال النسخة الحالية (قرار المالك).
